## Purpose

One pure function that turns a resolved Commander deck into a list of plain-dict rows, one per
distinct card, so a chat assistant can list the deck's cards and which functional roles each
fills. Do not add any other public function, class or constant.

## Module docstring (REQUIRED, keep it short)

Say: rows are the mentor's card-level view of the deck; role names come ONLY from
`redundancy.card_roles(tags.analyze(card))` (one taxonomy, never a new one); lands carry
`["land"]`; commanders are listed first and flagged.

## Imports (copy exactly; add nothing else)

```python
from __future__ import annotations

from mythgauntlet.model.deck import ResolvedDeck
from mythgauntlet.ratings import redundancy
from mythgauntlet.semantics import tags
```

Never write `from typing import dict/list/set/tuple` (they are builtins).

## Signature

```python
def deck_card_rows(resolved: ResolvedDeck) -> list[dict]:
```

## Inputs you may use (verified)

- `resolved.commanders`: `list[Card]`.
- `resolved.cards`: `list[tuple[Card, int]]` (card, quantity).
- `Card` has: `.name: str`, `.type_line: str`, `.mana_value: int` (a property), `.is_land: bool`
  (a property; True for any card whose type line contains "Land").
- `tags.analyze(card)` returns an effect vector; `redundancy.card_roles(vector)` takes it and
  returns `dict[str, float]` mapping role name -> strength (empty dict for a card with no
  role). Role names are the dict's KEYS.

## Output row shape

```python
{"name": str, "qty": int, "mana_value": int, "type_line": str, "roles": list[str]}
```

- `roles` = `sorted(redundancy.card_roles(tags.analyze(card)))` (sorted list of the dict keys)
  for a nonland card; exactly `["land"]` for a card with `.is_land` true (do NOT call tags on
  lands).
- Commanders come FIRST, in `resolved.commanders` order, with `qty` 1 and an extra key
  `"commander": True`. Their roles are computed the same way (land rule included).
- Every other row is for an entry of `resolved.cards`, in the given order, with its own `qty`
  and NO `"commander"` key.
- If the same card name appears twice in `resolved.cards`, merge into ONE row whose `qty` is the
  sum (keep first-seen order). A commander's name is never merged with a `resolved.cards` row;
  they stay separate rows.
